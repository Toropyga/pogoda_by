# Pogoda.by для Home Assistant — 0.1.0

Пользовательская интеграция на основе package `pogoda_by.yaml`. Получает фактическую погоду Белгидромета через RSS, а список стран и станций — через JSON API. Ключ API не нужен. Прогноз погоды не предоставляется.

## Установка

1. Скопируйте папку `custom_components/pogoda_by` из этого проекта в каталог конфигурации Home Assistant. Итоговый путь должен быть `/config/custom_components/pogoda_by/manifest.json`.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Pogoda.by**.
4. Выберите страну из справочника, затем станцию из списка этой страны. В подписи станции указан её действительный ID, а не номер строки в JSON.
5. Дождитесь первого успешного получения RSS. Если станция не публикует поддерживаемую погоду, форма сообщит об этом и позволит выбрать другую.

Для нескольких станций добавьте интеграцию несколько раз. Повторное добавление одной станции блокируется. Для смены станции добавьте новую запись и удалите старую, когда она больше не требуется.

Это предварительная версия. Исходный код: https://github.com/Toropyga/pogoda_by. Для установки скачайте репозиторий через **Code → Download ZIP** и распакуйте его. Не копируйте весь проект в `custom_components`: туда нужна только вложенная папка `pogoda_by`. Отдельный релиз и установка через HACS пока не настроены.

## Сенсоры

Сенсор создаётся, когда соответствующее поле впервые появится в RSS. Если поле появится позже, перезапуск не нужен. Если ранее доступное поле пропадёт, сенсор станет недоступен; нулевые значения не подставляются.

| Поле | Единица / тип | Дополнительные сведения |
| --- | --- | --- |
| Температура | °C | Поддерживаются знак минус, точка и запятая |
| Атмосферное давление | hPa | Атрибут `status`: тенденция из RSS |
| Тенденция давления | Текст | Например, «падает» |
| Скорость ветра | m/s | `direction` и `speed_kmh`; единицы можно менять в Home Assistant |
| Направление ветра | Текст | Без подмены штиля северным направлением |
| Погода | Текст | Полное описание и исходная строка в атрибутах |
| Время наблюдения | Timestamp | Время `pubDate`, приведённое к UTC; интерфейс отображает местное время |
| Метеостанция | Диагностический текст | ID, страна, имя, координаты, часовой пояс, ICAO, ссылка |
| Влажность | % | Только если RSS явно содержит это поле |
| Порывы ветра | m/s | Только если RSS явно содержит это поле |
| Видимость | km | Только если RSS явно содержит это поле в километрах |

Влажность, порывы и видимость предусмотрены разборщиком как дополнительные поля, но их наличие в текущем сервисе не подтверждено. Интеграция не вычисляет их из других данных.

Каждая станция представлена отдельным устройством. У сущностей стабильные unique_id, основанные на стране, ID станции и типе показателя. Имена entity_id назначает Home Assistant; старые entity_id из package автоматически не переносятся.

Интервал по умолчанию — **10 минут**. Кнопка **Настроить** в записи интеграции позволяет выбрать от 5 до 180 минут. На один цикл приходится один RSS-запрос для всех сенсоров станции. Справочник загружается при настройке; информация о выбранной станции сохраняется в записи и не требует повторной загрузки при старте Home Assistant.

При ошибке HTTP, тайм-ауте или некорректном RSS погодные сенсоры становятся недоступны. Home Assistant повторяет обновление автоматически. Диагностический сенсор станции хранит локально сохранённые метаданные и остаётся доступен. Успешный ответ с устаревшей датой не считается сетевой ошибкой: проверяйте время наблюдения. Интеграция не обещает, что сама станция публикует новые измерения каждые 10 минут.

Сенсор `weather` с прогнозом не создаётся; для вывода используйте карточки сущностей, плитки и графики сенсоров. Числовые показатели имеют device_class, state_class и стандартные единицы Home Assistant.

## Переход с package

1. Сохраните резервную копию `pogoda_by.yaml`.
2. Установите интеграцию и убедитесь, что нужная станция возвращает корректные значения.
3. Отключите прежний package и перезапустите Home Assistant, чтобы прекратить двойной опрос и освободить прежние имена сущностей.
4. Обновите карточки и автоматизации на новые сущности либо вручную назначьте новым сущностям прежние entity_id после удаления старых конфликтующих сущностей.

| Было в package | Новая сущность / атрибут |
| --- | --- |
| `sensor.pogoda_by_json` | Метеостанция: ID, координаты и остальные атрибуты |
| `sensor.pogoda_by_rss` | Погода → `raw_description`; Время наблюдения → `published` |
| `sensor.pogoda_by_temperature` | Температура |
| `sensor.pogoda_by_pressure` | Атмосферное давление; атрибут `status` сохраняет смысл |
| `sensor.pogoda_by_wind` | Скорость ветра; `direction`, числовой `speed_kmh` |
| `sensor.pogoda_by_weather` | Погода; полный текст в `description` |

Устаревший атрибут ветра `speed` со строкой «… км/ч» заменён числовым `speed_kmh`. Отдельный `status` погоды не создаётся: текст после запятых сохраняется в общем описании без потери информации. Это важно учесть в существующих шаблонах.

## Проверка

Тесты разбора JSON/RSS используют стандартную библиотеку Python и образец из исходного package:

```powershell
python -m unittest discover -s tests -v
```

Проверка текущих ответов сайта без установки Home Assistant:

```powershell
python tools/check_live.py --country BY --station 26851
python tools/check_live.py --country PL --station 12372
```

Скрипт только читает открытые данные. Он не меняет конфигурацию Home Assistant. Для диагностики сообщений интеграции можно временно включить:

```yaml
logger:
  logs:
    custom_components.pogoda_by: debug
```

## Статус проверки этой сборки

Проверка синтаксиса, согласованности переводов и автономные тесты выполняются локально; итог записан в `VALIDATION.md`. Установленного тестового Home Assistant в среде разработки нет. Прямой доступ к API/RSS в этой среде не работает, поэтому фактические ответы сайта и полный процесс установки в работающий Home Assistant требуют проверки. Справочник поддерживает структуры «страна → массив станций» и «страна → объект станций», основанные на устройстве вашего package. Неизвестные изменения схемы API приводят к сообщению об ошибке, а не к созданию фиктивных данных.

Используются стандартные API ConfigFlow, OptionsFlow, DataUpdateCoordinator и SensorEntity. Целевая минимальная версия: Home Assistant 2025.1; фактическая совместимость ещё не подтверждена запуском внутри Home Assistant.
