# Pogoda.by Card — 0.2.0

Карточка фактической погоды для интеграции Pogoda.by. Работает без сторонних карточек, CDN и сборки JavaScript. Интерфейс: русский, белорусский, польский, английский и немецкий; по умолчанию используется язык Home Assistant.

## Совместная установка с интеграцией

Начиная с **Pogoda.by 0.2.0**, карточка поставляется внутри интеграции: `custom_components/pogoda_by/frontend/pogoda-by-card.js`. Она устанавливается и обновляется тем же пакетом, что и датчики. Отдельный репозиторий карточки и папка `/config/www` не требуются.

1. Установите или обновите **интеграцию Pogoda.by** и перезапустите Home Assistant. Для ручной установки скопируйте всю папку `custom_components/pogoda_by` в `/config/custom_components/`, включая `frontend`, `brand` и `translations`.
2. При первой настройке добавьте интеграцию и выберите станцию. При обновлении существующие станции сохраняются.
3. Обновите страницу браузера. При обычном управлении ресурсами через интерфейс интеграция сама добавляет **JavaScript module** с адресом `/pogoda_by/pogoda-by-card.js?v=0.2.0`.
4. На панели выберите **Редактировать → Добавить карточку → Pogoda.by Card**, выберите станцию и сохраните.

Автоподключение выполняется один раз для всей интеграции, а не для каждой станции. Оно обновляет URL при смене версии интеграции. Саму карточку на нужной панели размещает пользователь. Регистрация ресурса выполняется до первого запроса погоды и не зависит от доступности Pogoda.by.

### Переход с отдельной карточки 0.1.0

Если ресурс был добавлен по прежней инструкции как `/local/pogoda-by-card.js?v=0.1.0`, интеграция заменит его запись на новый адрес автоматически. Дубликаты только этих двух известных локальных адресов объединяются. Остальные ресурсы сохраняются, а старый файл в `/config/www` не удаляется. После обновления перезагрузите страницу браузера.

### Ресурсы управляются через YAML

Если используется **`resource_mode: yaml`**, интеграция публикует JavaScript, но не меняет пользовательскую конфигурацию. В уже существующий раздел `lovelace` в `configuration.yaml` добавьте ресурс (не создавайте второй одноимённый раздел):

```yaml
lovelace:
  resource_mode: yaml
  resources:
    - url: /pogoda_by/pogoda-by-card.js?v=0.2.0
      type: module
```

На Home Assistant до 2026.2 сохраните существующий `mode: yaml` вместо нового `resource_mode`. Не переключайте режим всей панели ради карточки. Выполните `lovelace.reload_resources` или перезапустите Home Assistant и обновите браузер. При следующих обновлениях поменяйте версию в этом URL вручную. Это исключение относится именно к способу управления ресурсами, а не к формату отдельных панелей: панель YAML может использовать ресурсы из интерфейса.

Если ресурсы управляются через интерфейс, этот YAML не нужен. При ошибке автоматической регистрации используйте тот же URL с типом **JavaScript module** в **Настройки → Панели управления → меню ⋮ → Ресурсы**; причина ошибки будет в журнале `custom_components.pogoda_by`.

## Настройка карточки

```yaml
type: custom:pogoda-by-card
station: BY_26850  # Пример: код страны и реальный ID вашей станции.
show_details: true
show_graph: true
show_observation: true
hours_to_show: 24
stale_after: 180
compact: false
language: auto
```

Станцию удобнее выбирать в редакторе. Значение `station` хранится в формате `КОД_СТРАНЫ_ID_СТАНЦИИ`, совпадающем с `unique_id` датчиков интеграции. Карточка читает реестр сущностей Home Assistant и определяет датчики по их стабильным идентификаторам, поэтому пользовательские имена и переименованные `entity_id` поддерживаются. В одном интерфейсе можно разместить несколько карточек разных станций.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `station` | Не выбрана | Станция интеграции; выбирается через интерфейс |
| `name` | Название станции | Собственный заголовок |
| `show_details` | `true` | Ветер, давление и дополнительные доступные показания |
| `show_graph` | `true` | График температуры из истории Home Assistant |
| `show_observation` | `true` | Дата и время наблюдения |
| `hours_to_show` | `24` | Длительность истории: целое число от 1 до 168 часов |
| `stale_after` | `180` | Считать наблюдение устаревшим через заданное число минут; от 5 до 10080 |
| `compact` | `false` | Уменьшенные размеры и отступы |
| `language` | `auto` | `auto`, `ru`, `be`, `pl`, `en`, `de` |
| `entities` | Автоматически | Явное сопоставление датчиков в YAML, если реестр недоступен |

Нажатие на температуру или показатель открывает обычное окно подробностей сущности Home Assistant. Цвета следуют текущей теме; предусмотрены размеры для телефона и раскладок Sections/Masonry. Текст погоды, направление ветра и тенденция давления сохраняются на языке источника.

## Данные и ограничения

- Прогноз не отображается: интеграция получает фактические наблюдения.
- Единицы измерения берутся из датчиков Home Assistant. Карточка не выполняет повторное преобразование температуры или давления.
- Влажность, порывы и видимость отображаются только при наличии доступных датчиков. Отсутствие показаний не заменяется нулём.
- Индикатор свежести использует датчик **времени наблюдения**, а не время очередного запроса RSS. По умолчанию порог — 3 часа; подберите его под частоту публикаций станции. Время на карточке показывается в часовом поясе, заданном в Home Assistant.
- При отсутствии корректного времени наблюдения карточка показывает это явно. Время более чем на пять минут в будущем также считается некорректным.
- График использует стандартную карточку `history-graph` через `loadCardHelpers`. Нужны Recorder/History и записанная история датчика температуры. Новая установка может ещё не иметь истории; датчик также может быть исключён из Recorder. Карточка сама не запрашивает Pogoda.by и не меняет интервал обновления интеграции.
- Встроенные компоненты Home Assistant могут меняться между версиями. Проверка в установленном Home Assistant остаётся необходимой; локальный демонстрационный стенд не заменяет её.

## Явное сопоставление сущностей

Если читать реестр не удаётся, укажите реальные `entity_id` вручную. Названия ниже — примеры; замените их значениями из **Инструменты разработчика → Состояния**. `station` можно не указывать при явном сопоставлении; с указанной станцией `entities` переопределяет отдельные автоматически найденные датчики.

```yaml
type: custom:pogoda-by-card
name: Моя метеостанция
show_graph: true
entities:
  temperature: sensor.my_temperature
  condition: sensor.my_weather
  pressure: sensor.my_pressure
  pressure_trend: sensor.my_pressure_trend
  wind_speed: sensor.my_wind_speed
  wind_direction: sensor.my_wind_direction
  observation_time: sensor.my_observation_time
```

Допустимы также ключи `station`, `humidity`, `wind_gust` и `visibility`. Необязательные датчики, которых у вас нет, добавлять не нужно.

## Обновление и диагностика

При обновлении заменяется вся интеграция; в обычном режиме URL ресурса обновляется автоматически. Перезапустите Home Assistant и обновите браузер. Если отображается `Custom element doesn't exist: pogoda-by-card`, проверьте запуск интеграции, ресурс и кэш браузера. По адресу `/pogoda_by/pogoda-by-card.js?v=0.2.0` должен открываться JavaScript, а не страница ошибки. В режиме ресурсов YAML обновите запись вручную.

Если станция не найдена, проверьте, что интеграция настроена и её сущности включены. Переименования поддерживаются, но ID станции должен соответствовать установленной записи интеграции. При недостаточных правах используйте `entities`.

## Локальная проверка разработчиком

```powershell
node --check custom_components/pogoda_by/frontend/pogoda-by-card.js
python -m unittest discover -s tests -v
node --test tests/test_card.cjs
node tools/test_card.cjs
```

Для проверки логики достаточно Node.js 22+: `node --test tests/test_card.cjs` запускает тесты с минимальным имитатором DOM. Эта проверка не оценивает внешний вид.

Для `tools/test_card.cjs` дополнительно нужен установленный Chrome. Другой путь к браузеру задаётся переменной `CHROME_BIN`. Этот тест использует временный профиль, локальный HTTP-сервер и демонстрационный объект `hass`; проверяет привязку переименованных сущностей, отсутствие и устаревание данных, редактор, историю и мобильную ширину. Он не подключается к Home Assistant.

Для ручного предпросмотра запустите `python -m http.server 8765 --bind 127.0.0.1` из корня проекта и откройте `http://127.0.0.1:8765/tools/card-preview.html`. Все показатели и график в этом предпросмотре демонстрационные.
