# Проверка версии 0.2.1

Дата: 13 ноября 2026 года.

Подготовлены два вида карточки: полный по умолчанию и отдельная компактная компоновка (`compact: true`). В компактном виде отображаются станция, значок, температура и описание погоды, краткие показатели ветра и давления, статус свежести и время наблюдения. График и необязательные показатели не отображаются; параметры полного вида сохраняются при переключении. Редактор предлагает выбор вида на пяти языках. Размер по умолчанию для компактного вида — шесть колонок Sections, с адаптацией к узкому контейнеру.

Проверки: **50 Python-тестов и 26 тестов логики карточки**. Новые сценарии подтверждают отличия компоновок, сохранение параметров полного вида, скрытие блоков, состояния устаревания и недоступности, отмену незавершённого создания графика при переходе в компактный вид, логический тип параметра в редакторе и экранирование текста в подсказках.

Страница `tools/card-preview.html` показывает оба вида на одних демонстрационных данных. В `tools/test_card.cjs` добавлены браузерные проверки высоты компактного вида и ширины 180 px. Эти браузерные проверки пока не выполнены: ограничения среды запуска браузера, отмеченные ниже, сохраняются. Визуальная проверка в работающем Home Assistant и график с реальной историей Recorder ещё требуются.

Версии manifest, Python и JavaScript согласованы на 0.2.1; примеры ресурсов используют `/pogoda_by/pogoda-by-card.js?v=0.2.1`. Встроенный ресурс YAML нужно обновить вручную, затем перезагрузить ресурсы и обновить браузер. Данные и идентификаторы настроенных станций не меняются.

# Проверка версии 0.2.0

Дата: 13 ноября 2026 года.

Подготовлен совместный выпуск интеграции и Pogoda.by Card 0.2.0. JavaScript входит в `custom_components/pogoda_by/frontend/`; ресурс автоматически регистрируется в Lovelace storage при общем setup интеграции. URL содержит версию интеграции. Прежняя ручная запись `/local/pogoda-by-card.js` переносится на новый адрес; известные локальные дубликаты объединяются после загрузки существующей коллекции ресурсов. Ресурсы YAML остаются под управлением пользователя.

Все пять актуальных README согласованы с версией 0.2.0: английский — `README.md`; переводы — `docs/README.ru.md`, `docs/README.pl.md`, `docs/README.be.md`, `docs/README.de.md`. Описаны совместная установка, визуальный редактор карточки, пример конфигурации, обновление, YAML-ресурсы и ограничения. Обновлены CHANGELOG, инструкции установки и карточки. Исторические записи ниже описывают предыдущие сборки.

Проверки подготовленного выпуска:

- `python -m unittest discover -s tests -v`: **50 тестов** — разбор данных, транспорт, комплектность, переводы и регистрация ресурсов на имитаторах API.
- `node --test tests/test_card.cjs`: **18 тестов** логики карточки с минимальным имитатором DOM.
- `node --check custom_components/pogoda_by/frontend/pogoda-by-card.js` и `node --check tools/test_card.cjs`: проверка синтаксиса JavaScript.
- `git diff --check` и `git diff --cached --check`: проверка пробелов рабочего дерева и подготовленного коммита.
- Проверка согласованности версии в manifest, Python-константе, JavaScript, README и примерах URL; проверка относительных ссылок Markdown и установочного архива.

Отдельно проверены сохранение посторонних ресурсов, повторный запуск и конкурентная регистрация для восьми станций, обновление URL, миграция ручного ресурса, режим YAML и отказы API регистрации. Встроенный график использует стандартную карточку History и нуждается в записанной истории Recorder. Карточка не запрашивает Pogoda.by отдельно от интеграции и не создаёт прогноз.

Полная установка в работающем Home Assistant, визуальное отображение, настоящий график Recorder и текущие ответы API/RSS пока не подтверждены. Инструкция карточки: [docs/CARD.ru.md](docs/CARD.ru.md). Автономные проверки не заменяют проверку совместимости с действующей системой.

# Проверка версии 0.1.4

Дата: 13 ноября 2026 года.

Добавлен немецкий перевод интерфейса `custom_components/pogoda_by/translations/de.json` с полным набором ключей (шаги ConfigFlow и OptionsFlow, ошибки, названия всех сенсоров). Проверка соответствия ключей (`tests/test_bundle.py::test_translations_have_matching_keys`) расширена с четырёх до пяти языков (`en`, `ru`, `be`, `pl`, `de`) и подтверждает полное совпадение ключей с `strings.json`, включая плейсхолдер `{country}` в описании шага выбора станции. Отображение немецкого перевода в работающем Home Assistant не проверялось.

Подготовлен немецкий README (`docs/README.de.md`) по структуре остальных языковых версий. Раздел «Языки интерфейса» обновлён во всех README: теперь перечислены белорусский, польский, русский, английский и немецкий языки.

Переведённые README вынесены из корня репозитория в папку `docs/`: `docs/README.en.md`, `docs/README.pl.md`, `docs/README.be.md`, `docs/README.de.md`. Русский `README.md` остаётся в корне репозитория, так как GitHub и HACS/Marketplace по умолчанию ищут файл README именно там. Внутренние ссылки исправлены: из корневого `README.md` ссылки на переводы ведут в `docs/...`; внутри файлов `docs/*.md` ссылка на русскую версию ведёт в `../README.md`, а ссылка на `HACS.md` — в `../HACS.md`; ссылки между языковыми версиями внутри `docs/` остаются относительными без изменений. Ссылки на README в `CHANGELOG.md` также обновлены на новые пути.

При вычитке переведённых README на орфографию и грамматику найдены и исправлены ошибки:
- белорусская версия (`docs/README.be.md`): несогласование рода «Важнае заўвага» → «Важная заўвага» (слово «заўвага» жаночага роду); русизм «часто» → «часта»; калька «частична» → «частковая» (беларускі корань «частка/частковы», а не «частичны»);
- немецкая версия (`docs/README.de.md`): устранена бессоюзная конструкция (запятая вместо союза) во вступительном абзаце;
- английская версия (`docs/README.en.md`): добавлен пропущенный артикль «The integration supports…», а также восстановлены немецкая ссылка и упоминание языка `de` в разделе «Interface languages», пропущенные при предыдущем обновлении.
Польская и русская версии при вычитке ошибок не показали.

- **36 автономных тестов пройдены** после всех изменений, ошибок и пропусков нет (`python -m unittest discover -s tests -v`).
- Проверка ключей переводов пройдена для пяти языков вместо четырёх.
- Перемещение README в `docs/` не затронуло `custom_components/`, `hacs.json` и `manifest.json`; ссылок на расположение README в этих файлах не было.
- Сетевая проверка `tools/check_live.py` и запуск в работающем Home Assistant в рамках этого обновления не выполнялись: изменения ограничены переводами, README и ссылками между документами, исполняемый код не менялся.

# Проверка версии 0.1.1

Дата: 12 ноября 2026 года.

Интервал по умолчанию увеличен с 10 до 60 минут. Явно сохранённые пользовательские интервалы сохраняются.

Добавлена утверждённая иконка с надписью Pogoda.by. Созданы `brand/icon.png` (256×256) и `brand/icon@2x.png` (512×512); размеры, PNG-формат и прозрачность проверены. Скрипт `tools/build_brand.ps1` выполнен успешно. Подключение использует стандартную локальную папку `brand`, поддерживаемую Home Assistant с версии 2026.3. Отображение в работающем Home Assistant не проверялось.

Для Marketplace / HACS добавлен корневой `hacs.json`, подготовлены инструкции установки и публикации. Структура комплекта проверена перед упаковкой. Установка через работающий Marketplace / HACS и официальный сетевой валидатор HACS не запускались. Соответствие локальной структуры требованиям не является подтверждением завершённой установки.

Добавлена белорусская локализация `be.json`, уточнены польские формулировки настроек обновления. Генератор переводов и существующая проверка ключей расширены на четыре языка. Проверяются сообщения настройки, ошибки, параметры обновления и названия всех сенсоров. Текстовые данные самого RSS сохраняются на языке источника. Отображение переводов в работающем Home Assistant не проверялось.

Подготовлены полные переводы README на английский, польский и белорусский языки с навигацией между четырьмя версиями. Во всех версиях учтён встроенный Marketplace в Home Assistant 2026.11 и новее; прежний HACS описан отдельно для версий до 2026.11. Инструкции сверены с официальной документацией Marketplace. Проверяются полнота разделов, таблиц, совпадение команд и относительные ссылки. Эти изменения относятся к документации и не меняют версию исполняемого кода.

По запросу владельца весь подготовленный комплект выпускается как **0.1.1**, независимо от промежуточной локальной нумерации. Версия manifest и заголовки README согласованы с выпуском. Описание релиза на русском и английском сохранено в `RELEASE_NOTES.md`.

- **36 автономных тестов пройдены**, ошибок и пропусков нет (`python -m unittest discover -s tests -v`).
- 25 тестов проверяют разбор справочника, RSS и дат, включая пример из исходного package.
- 7 тестов проверяют HTTP-обработчик с подставным транспортом: сетевые ошибки, тайм-аут, ошибочный HTTP-статус, неверный JSON/кодировку, размер ответа, передачу ID станции. Они не проверяют реальное сетевое соединение и совместимость с установленным aiohttp.
- 4 проверки комплекта: синтаксис всех Python-файлов, manifest, соответствие ключей переводов и названий сенсоров.
- Проверка `compileall` завершена успешно.
- Ключи интерфейса на английском, русском, белорусском и польском языках согласованы.
- Проверка живого API скриптом `tools/check_live.py` не прошла: DNS-запрос завершился ошибкой `getaddrinfo failed`. Считать это подтверждением недоступности сайта для пользователя нельзя.
- Рабочий Home Assistant не изменялся. Установка, формы настройки, реальные обновления сенсоров, выгрузка интеграции и совместимость с конкретной версией Home Assistant пока не проверены запуском в Home Assistant.

Для завершения проверки в рабочем окружении: установить интеграцию вручную по README, выбрать страну и станцию, проверить первое и следующее обновления, изменение интервала и повторный запуск Home Assistant. Для быстрой проверки схемы данных без установки предусмотрен `tools/check_live.py`.
